## Dependencies {#dependencies}

```bash npm2yarn
npm install @mui/material @emotion/react @emotion/styled @mui/icons-material lodash
```
## Why Player? {#why}

- **Separate video and audio files, kept in sync.** A video-only file and an audio file play through plain `<video>` and `<audio>` tags, and the player corrects drift while they play. If they keep drifting, it falls back to audio only.
- **Audio outlives the video.** Remove `VideoPlayer`, e.g. on a page change, and the audio keeps playing in the [mini player](#mini-player-and-playlist). Load it again and the video catches up.
- **Playlists,** with next and previous also on the keyboard media keys and the phone's lock screen.
- **Its own subtitle renderer** for `.vtt`, `.srt` and `.ass`, keeping `.ass` fonts, colours and positions. Viewers can restyle and retime them, and make the text selectable for pop-up dictionaries. See [Subtitles](#subtitles).
- **Subtitle tracks inside MKV and MP4 files,** read with range requests, so the file is never downloaded for them. See [MKV and MP4 files](#mkv-files).
- **180°, 360° and 3D videos,** with drag to look around and a VR mode. See [180°, 360° and 3D](#180-360-and-3d).
- **Background bloom:** a soft glow behind the player, drawn from the video's own frames.
- **Video filters and audio effects** for viewers: colour presets, brightness and contrast, bass, mid and treble, volume boost, night mode and an audio offset.
- **Move and zoom** the video, and a [sticky player](#sticky-mobile-player) on mobile.


## Usage {#usage}

```tsx
import {
  AudioHolder,
  MiniPlayer,
  PlayerContextProvider,
  usePlayer,
  VideoPlayer,
} from "@arclockproject/common/components/Player";
```

A video and audio player made of parts that share one state:

- `PlayerContextProvider` holds the state. Put it high in the tree so playback survives page changes.
- `VideoPlayer` shows the video and controls.
- `AudioHolder` plays the audio. Keep it mounted so audio keeps playing when `VideoPlayer` is removed.
- `MiniPlayer` is a small player bar fixed to the bottom-right of the screen.
- `usePlayer` gives your own components access to the state.

The settings button in the controls and right-click open the same menu: loop, subtitles, video filters, audio effects, 180°/360°/3D and debug info. To move or zoom the video, pick **Move and zoom** there. Then drag it, use the mouse wheel or pinch. Taps on the video don't play, pause or seek until you press **Done** or `Esc`. The position and zoom stay after **Done**. To undo them, press **Reset**, or pick **Reset move and zoom** in the menu.

The examples below are live. Edit the code to try your own values.

### Single video {#single-video}

Pass `videoData` to load an entry as soon as the player mounts.

```tsx live showLineNumbers
<PlayerContextProvider>
  <div
    style={{
      width: "80%",
      maxWidth: "600px",
    }}
  >
    <VideoPlayer
      videoData={{
        files: {
          video: `${REMOTE.base}/PXQZNGjZIFo.mp4`,
          audio: `${REMOTE.base}/PXQZNGjZIFo.m4a`,
          subtitles: null,
          thumbnail: `${REMOTE.base}/PXQZNGjZIFo.webp`,
        },
        id: "original-2-eis3",
        title: "Original Piece #2 by Eis3",
        meta: null,
      }}
      isPlaylist={false}
      chapters={[]}
      heatmap={[]}
      showInlineTitle
    />
    <AudioHolder />
  </div>
</PlayerContextProvider>
```

### Subtitles {#subtitles}

Set `files.subtitles` to a `.vtt`, `.srt` or `.ass`/`.ssa` file. The player draws them itself, so they also show in audio only mode and for videos without a separate audio file. `.ass` fonts, colours, outlines and positions are kept. Animations (`\t`, `\fad`, karaoke) are not played, and fonts must be installed on the viewer's device. Files on another origin need CORS headers.

Viewers turn subtitles on with `C`, the subtitles button in the controls or the settings menu. **Subtitle settings** changes the size, colour, background, height and timing, and can turn off the file's own styles. **Selectable text** lets viewers select the lines and point at them, e.g. with a pop-up dictionary like Yomitan. Clicks on the text then don't play or pause, and right-click opens the browser's own menu, e.g. to copy. These settings are saved.

Play the video and press `C`. The file below is `.ass`, passed as a `data:` URL.

### MKV and MP4 files {#mkv-files}

An `.mkv` file is passed to the `<video>` element as it is, so whether it plays depends on the browser. Chromium-based browsers play most MKV files with H.264 video and AAC audio. Other browsers may not play them at all. Audio in a codec the browser can't decode (AC3, DTS) is silent.

Text subtitle tracks inside the video are listed after the entry's own subtitle files, named after the track's name or language:

- `.mkv` and `.webm`: `.srt`, `.ass` and WebVTT tracks.
- `.mp4`, `.m4v` and `.mov`: `tx3g` (`mov_text`, what `ffmpeg` writes) and WebVTT tracks.

The player reads only the start of the video, its index and the subtitle lines, with range requests, so the whole file is never downloaded for them. Lines show up while the track loads. This needs:

- A server that supports range requests. Files on another origin also need CORS headers.
- For `.mkv`, an index that lists the subtitle blocks. `mkvmerge` and `ffmpeg` write one.

Image subtitles (PGS, VobSub), TTML, fonts inside the file and fragmented MP4 files are not supported. Turn the tracks off with `settings.embeddedSubtitles`.

### 180°, 360° and 3D {#180-360-and-3d}

Set `format` on the entry for videos that aren't flat. In 180° and 360° videos, viewers drag to look around and scroll or pinch to zoom. Taps still play and pause. In 180°, everything behind the viewer is black. 3D videos (`stereo`) hold one picture per eye. Outside VR, only the left eye is shown, stretched back to its real shape.

Viewers can also set the format themselves in **180°, 360° and 3D** in the settings menu, for entries without `format`. In browsers with a VR headset, the menu has **Enter VR**, which shows each eye on its own side.

180° and 360° need the video's pixels, so the file must come from the same origin as the page, or `settings.corsMedia` must be on with a server that sends CORS headers. Otherwise the video is shown flat.

```tsx
<VideoPlayer
  videoData={{
    id: "my-vr180-clip",
    title: "VR180 clip",
    files: { video: "/videos/clip.mp4", audio: null, subtitles: null, thumbnail: "/videos/clip.webp" },
    meta: null,
    format: { projection: "180", stereo: "sbs" }, // VR180: side by side, one 180° half-sphere per eye
  }}
  isPlaylist={false}
  chapters={[]}
  heatmap={[]}
/>
```

### Mini player and playlist {#mini-player-and-playlist}

Load a video, then press **VideoPlayer Unload**. As long as `<AudioHolder />` stays mounted,
the audio keeps playing in the mini player. When the player is loaded again, it syncs back.

```tsx live showLineNumbers
function main() {
  function PageWithPlayer() {
    let exampleVideos = [
      {
        files: {
          video: `${REMOTE.base}/PXQZNGjZIFo.mp4`,
          audio: `${REMOTE.base}/PXQZNGjZIFo.m4a`,
          subtitles: null,
          thumbnail: `${REMOTE.base}/PXQZNGjZIFo.webp`,
        },
        id: "original-2-eis3",
        title: "Original Piece #2 by Eis3",
        meta: null,
      },
      {
        files: {
          video: `${REMOTE.base}/jkZ53T1Pu7k.mp4`,
          audio: `${REMOTE.base}/jkZ53T1Pu7k.m4a`,
          subtitles: null,
          thumbnail: `${REMOTE.base}/jkZ53T1Pu7k.webp`,
        },
        id: "original-3-eis3",
        title: "Original Piece #3 by Eis3",
        meta: null,
      },
    ];
    const player = usePlayer();
    return (
      <div>
        <div
          style={{
            width: "80%",
            maxWidth: "600px",
          }}
        >
          <VideoPlayer
            isPlaylist={false}
            chapters={[]}
            heatmap={[]}
            showInlineTitle
          />
          {player.internal.playerData.value !== null && (
            <button
              onClick={() => player.internal.playlistContent.set(exampleVideos)}
            >
              Load All (playlist)
            </button>
          )}
          {exampleVideos.map((entry) => (
            <button
              onClick={() => player.internal.playerData.set(entry)}
              key={entry.id}
            >
              {entry.title}
            </button>
          ))}
        </div>
      </div>
    );
  }

  function App() {
    const [page, setPage] = useState(0);
    return (
      <>
        <div>
          <button onClick={() => setPage(0)}>VideoPlayer Unload</button>
          <button onClick={() => setPage(1)}>VideoPlayer Load</button>
        </div>
        <div style={{ width: "80%", maxWidth: "600px" }}>
          {page === 0 ? <p>VideoPlayer not rendering</p> : <PageWithPlayer />}
        </div>
      </>
    );
  }

  return (
    <PlayerContextProvider>
      <div style={{ height: "400px" }}>
        <App />
      </div>
      {/*<MiniPlayer /> // Toggleable by using internal for now */}
      <AudioHolder />
    </PlayerContextProvider>
  );
}
```

### Sticky mobile player {#sticky-mobile-player}

With `sticky: true`, the video stays at the top on mobile while the page scrolls below it. Triggers at about 600px width.

```tsx live showLineNumbers
<PlayerContextProvider
  settings={{
    autoAudioOnly: false,
    autoPlay: false,
    videoBackgroundBloom: true,
    allowMiniPlayer: true,
    sticky: true, // changed
    stickySpacing: 0, // Gap above the sticky player in px (e.g. for a navbar). Hidden while scrolling down.
    stickyTriggerDistance: 0, // Pixels to scroll before the gap hides or comes back. 0 is immidiate
  }}
>
  <div style={{ height: "500px", overflowY: "scroll" }}>
    <VideoPlayer
      videoData={{
        files: {
          video: `${REMOTE.base}/PXQZNGjZIFo.mp4`,
          audio: `${REMOTE.base}/PXQZNGjZIFo.m4a`,
          subtitles: null,
          thumbnail: `${REMOTE.base}/PXQZNGjZIFo.webp`,
        },
        id: "original-2-eis3",
        title: "Original Piece #2 by Eis3",
        meta: null,
      }}
      isPlaylist={false}
      chapters={[]}
      heatmap={[]}
      showInlineTitle
    />
    <div style={{ height: "500px" }}>
      I am 500px tall. If you view me on mobile, you will see that the video
      stays there and this text will go below the video as you scroll. Try to
      scroll and see me disappear!
      <br />
      <br />
      <br />
      <br />
      <br />
      <br />
      <br />
      <br />
      Still here!
    </div>
  </div>
  <AudioHolder />
</PlayerContextProvider>
```
